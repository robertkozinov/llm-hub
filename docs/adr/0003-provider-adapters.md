# 3. Адаптеры провайдеров

Статус: Принято · 2026-11-23

## Контекст
Варианты: официальные SDK провайдеров, langchaingo или свои адаптеры. SDK тянут зависимости и три разных стиля; langchaingo прячет детали потока и usage. Программа должна отличать «ошибся я» от «сломалось за шлюзом».

## Решение
**Адаптеры** пишем сами на `net/http` со своим разбором SSE: один для всех OpenAI-совместимых (OpenAI, Groq, DeepSeek, Ollama…), отдельно Anthropic и Gemini. OpenAI-совместимому в потоке всегда добавляем `stream_options.include_usage`; клиенту кусок с usage отдаём, только если он сам его просил.

**Ошибки** приводятся к виду `{"error":{"message","type","code"}}`:

| Провайдер | Шлюз |
|---|---|
| 400, 404, 422 и прочие 4xx | тот же код |
| 401, 403 | 502, `provider_auth_failed` |
| 429 | 429 + заголовок `Retry-After` |
| 5xx, недоступен | 502 |
| не ответил вовремя | 504 |

Обрыв посреди потока — последнее событие `data: {"error": {...}}` и закрытие без `[DONE]`. Клиент отключился — запрос к провайдеру сразу обрывается.

**Картинки во входе:** OpenAI-совместимым — как есть; для Anthropic и Gemini перекладываем в их формат; ссылку на картинку Gemini не принимает — пока отвечаем 400.

## Последствия
- Полный контроль над потоком, tool calls и ошибками; больше своего кода и тестов.
- 401 провайдера не путается с неверным паролем шлюза.
