# Решения (ADR)

Каждое решение — отдельный файл. Решения не переписываются задним числом: если передумали, пишется новое ADR, а старое получает статус «Заменено ADR N».

ADR пишем, только если решение касается обеих частей проекта или его дорого переделать потом. Мелочи — в коде и планах.

Статусы: **Принято** — делаем так. **Предложено** — ещё не согласовано между Робертом и Артёмом, полагаться нельзя.

## Ещё не решено
Обсудим, когда ядро начнёт работать с сервисом интеграций и GUI:
- контракты сервиса интеграций (:4100) и `/api/*` для GUI;
- если таблицами и миграциями владеет ядро (ADR 8), то как сервис интеграций хранит кэш каталога MCP: пишет в общий файл SQLite напрямую, ходит через ядро или держит свой файл;
- кто запускает сервис интеграций: по отчёту — ядро, как дочерний процесс. Связано с ADR 1.
