# 2. Шлюз в формате OpenAI

Статус: Принято · 2026-11-23

## Контекст
Сторонние программы уже умеют работать с OpenAI API; ТЗ (п. 3.1.2) требует совместимый шлюз. Одна модель может быть у нескольких провайдеров, допускается несколько экземпляров одного провайдера (`openai-work`).

## Решение
**Вход.** `http://127.0.0.1:4000/v1`: `POST /v1/chat/completions` (обычный и потоковый SSE, с tool calls) и `GET /v1/models`. Пускаем только по паролю (`Authorization: Bearer`), слушаем только 127.0.0.1, CORS не открываем.

**Формат внутри ядра** повторяет Chat Completions OpenAI, включая tool calls. Неизвестные поля запроса и ответа сохраняются и передаются дальше.

**Маршрутизация.** Провайдер определяется по `PROVIDER.code`:
- `<code>/<модель>` (остаток может содержать `/`) — запрос уходит этому провайдеру, даже если модели ещё нет в списке;
- иначе вся строка — имя модели, ищется в списке моделей: у нескольких провайдеров — 400 со списком вариантов, ни у кого — 404;
- провайдер по виду имени не угадывается.

## Последствия
- Агентный цикл (п. 5.3 отчёта) ляжет на тот же формат без переделки.
- До появления БД работает только явная форма `<code>/<модель>`; голое имя → 404 с подсказкой.
- Картинки-генерация, аудио, эмбеддинги и проброс в родном формате провайдера — позже.
